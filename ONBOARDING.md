# Онбординг для ученика (без опыта с кодом — это нормально)

Твоя цель — один раз настроить рабочее место. Дальше всю «программистскую» работу
делает ИИ-агент, твоя роль — дизайнерская: давать референсы, смотреть глазами
и утверждать на гейтах.

## Что нужно сделать руками (один раз)

### 1. Установи Claude Code

Скачай и установи по официальной инструкции: https://claude.com/claude-code
(есть десктоп-приложение — для старта проще всего оно).

### 2. Прими приглашение в репозиторий

Куратор пришлёт приглашение в приватный репозиторий `garaevruslan/design-kit`
на твою почту GitHub (если нет аккаунта GitHub — заведи на github.com, это
бесплатно и без карты). Открой письмо и нажми Accept.

### 3. Подключи инструмент дизайна (один из трёх — по матрице в README)

**Вариант А — Figma** (есть тариф Pro/Edu с местом редактора):
в Claude Code подключи официальный Figma MCP (в интерактивной сессии команда
`/mcp` → Figma → авторизация через браузер). Если застрял — скажи агенту
«помоги подключить Figma MCP», он проведёт.

**Вариант Б — Pencil** (бесплатно, early access):
скачай Pencil с https://www.pencil.dev (macOS: Apple Silicon/Intel;
Windows x64; Linux). Веб-версии нет — нужен установленный редактор, и он
должен быть ЗАПУЩЕН, когда агент работает. ИИ-функции Pencil работают через
твою подписку Claude. Подключение MCP к Claude Code — попроси агента:
«подключи Pencil MCP», он настроит и продиагностирует
(см. docs/pencil-path.md, раздел «Подключение»).

- **Windows-нюанс:** настройка Pencil MCP на Windows сложнее, чем на macOS:
  клиентов агента и вариантов приложения несколько, MCP-сервер привязывается
  к конкретному варианту (`-app …`), а копия сервера может быть старее
  приложения (симптом: агент «видит» документ, но скриншоты пустые). Не
  разбирайся руками — открой Pencil, скажи агенту «подключи Pencil MCP и
  проверь рендер тестовым скриншотом» и жди чек-листа. ARM64-сборки для
  Windows пока нет (x64 работает).

**Вариант В — без всего** (только браузер): ничего подключать не нужно,
агент соберёт HTML-прототип (docs/fallback-html.md).

### 4. Вставь этот промпт в Claude Code

Скопируй целиком и отправь одним сообщением:

```
Настрой мне рабочее место design-kit. Сделай сам всё, что можно сделать за меня,
а где нужно моё действие — давай инструкцию по одному шагу и жди.

1. Проверь, установлены ли git, GitHub CLI (gh) и Node.js. Чего нет — помоги
   установить (я на новичковом уровне, объясняй просто).
2. Авторизуй gh (gh auth login), если не авторизован — проведи меня по шагам.
3. Склонируй репозиторий garaevruslan/design-kit в папку, которую мы согласуем.
4. Установи скилл: скопируй skills/design-kit из репозитория в ~/.claude/skills/.
5. Спроси, каким путём я иду (Figma / Pencil / HTML — матрица в README).
   Для Figma: проверь, что Figma MCP подключён и авторизован (whoami).
   Для Pencil: проверь подключение Pencil MCP при запущенном приложении и
   сделай тестовый скриншот (docs/pencil-path.md, «Подключение»).
   Для HTML: ничего дополнительного.
6. Проверь браузерный MCP для извлечения референсов (chrome-devtools). Если
   нет — помоги установить.
7. В конце покажи чек-лист: что готово, что нет, и скажи фразу, которой я
   запускаю свой первый проект.
```

Агент пройдёт по списку и в конце скажет, что всё готово.

## Как запускать проекты (каждый раз)

Одно сообщение агенту:

```
Новый проект design-kit. Референс: <URL сайта или скриншоты>.
Продукт: <что за сайт делаем, кратко>.
```

Агент создаст папку проекта, извлечёт дизайн-систему из референса и будет
останавливаться на гейтах — читай, смотри в Figma и отвечай «утверждаю» или
пиши правки. Терминал тебе больше не нужен.

## Если что-то сломалось

Не гугли — опиши проблему агенту словами («на шаге X появилось вот это: …»)
и попроси починить. Это часть метода: агент — твой инженер.

## Обновления комплекта

Раз в некоторое время (или по объявлению куратора) скажи агенту:
«обнови мой design-kit» — он сделает `git pull` и расскажет, что изменилось.

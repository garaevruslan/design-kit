# Assembly: сборка макетов (фаза 5)

Правила фазы 5. Входы: утверждённая библиотека (гейт 3), утверждённый
`project/content-doc.md` (гейт 2), `project/reference-inventory.md`,
`project/tokens.json`. Выход: страницы в Figma (desktop + mobile) + источник
композиции каждой секции в worklog.

Работа в Figma — через Figma MCP. Перед вызовами `use_figma` обязателен скилл
`figma-use`; для сборки страниц и многосекционных вью — скилл
`figma-generate-design`. Нет доступа к Figma MCP → `docs/fallback-html.md`.

## `instances-only` — только инстансы

Макеты собираются исключительно из инстансов компонентов библиотеки, утверждённой
на гейте 3. Рисовать фреймы, кнопки, карточки «одноразово» прямо в макете запрещено.

Понадобился паттерн, которого в библиотеке нет:

1. Остановить сборку страницы.
2. Мини-возврат в фазу 4: создать компонент по `docs/figma-library-rules.md`
   (variables, варианты, мобильное поведение — полный стандарт, не «черновик на разок»).
3. Записать в worklog: какой секции не хватило компонента, что добавлено.
   Добавление компонента — Tier 1; повторное утверждение всей библиотеки не требуется,
   но новые компоненты предъявляются человеку на гейте 4 списком.
4. Вернуться в фазу 5 и поставить инстанс.

## `composition-cascade` — выбор композиции секции

Для каждой секции content-doc источник композиции выбирается по каскаду.
Процедура:

**Шаг 1 — референс.** Найти в `reference-inventory.md` аналог секции. Матчить
в два прохода: сначала по полю `type` (hero ↔ hero, pricing ↔ pricing), затем —
по назначению (секция «снять возражение о цене» может матчиться на faq или
comparison-таблицу референса, даже если типы не совпали буквально). Использовать
маппинг, предзаполненный в фазе 3, но перепроверить его: на гейте 2 утверждалась
структура, а не пригодность композиции. Аналог найден → взять его композицию
(анатомию секции: состав, иерархию, порядок зон) из inventory. Визуальные значения
при этом — только из tokens.json/variables, не из скриншота референса
(`reference-source-of-truth`).

**Шаг 2 — библиотека скелетов.** Аналога в референсе нет → искать скелет в
`library/skeletons/` по тем же ключам: тип секции, затем назначение. Скелет задаёт
анатомию; наполнение — контентом секции, визуальный слой — токенами проекта.

**Шаг 3 — invented.** Нет ни в референсе, ни в скелетах → агент компонует сам
строго в рамках системы (только компоненты библиотеки, только токены) и помечает
секцию `composition: invented`. Такие секции человек на гейте 4 проверяет
в первую очередь.

Для каждой секции в worklog фиксируется: id секции → источник
(`reference: <id из inventory>` / `skeleton: <файл>` / `invented`) + одна строка
мотивировки при неочевидном матче. Секция без записи об источнике = фаза не сдана.

## Порядок сборки

Страница за страницей, внутри страницы — секция за секцией сверху вниз в порядке
content-doc. Не собирать все страницы «широким фронтом»: ошибка, найденная на первой
странице, не должна успеть размножиться.

1. Создать оба фрейма страницы (desktop + mobile).
2. Секция за секцией: выбрать источник композиции (каскад) → поставить инстансы →
   залить контент → сразу проверить секцию на обеих ширинах.
3. После завершения страницы — промежуточный скриншот-чек: снять скриншот обоих
   фреймов целиком, осмотреть на очевидные дефекты (переполнение, разъехавшийся
   autolayout, пустые инстансы, выпавшие секции), исправить до перехода к следующей
   странице. Результат чека — строкой в worklog.

## Фреймы и брейкпоинты

- Каждая страница = минимум два фрейма: desktop и mobile (ширины — из брейкпоинтов
  tokens.json; по умолчанию 1440 и 390).
- Имена фреймов: `<page>/<breakpoint>`, где `<page>` — id страницы из content-doc:
  `home/desktop-1440`, `home/mobile-390`, `pricing/desktop-1440`.
- Мобильный фрейм — не уменьшенная копия: применять «Мобильный приоритет» каждой
  секции из content-doc (что свернулось, что скрылось, что сменило порядок)
  и мобильные варианты компонентов.

## Autolayout

Autolayout обязателен на всех уровнях: фрейм страницы, секции, внутренние группы.
Абсолютное позиционирование — только для осознанных декоративных наложений,
каждое такое исключение фиксируется в worklog поимённо. Проверяется аудитом фазы 6.

## Тексты

- Тексты переносятся из content-doc дословно. Самовольная правка — переформулировать,
  сократить, «улучшить», поменять регистр CTA — запрещена. Текст кажется неудачным
  или не подходит секции → вопрос человеку, не молчаливая правка.
- Текст переполняет компонент или не влезает (обрезка, перенос, разрыв сетки) —
  это сигнал к правке компонента (мини-возврат в фазу 4: авторазмер, min/max,
  поведение переноса), а не к ручному костылю в макете. Запрещено: локально менять
  размер шрифта, сжимать трекинг, руками растягивать инстанс, отвязывать текстовый
  стиль. Если честная правка компонента не решает — вопрос человеку о сокращении
  текста (правка текста = правка content-doc, Tier 0, через человека).

## Плейсхолдеры ассетов

По `placeholders-for-assets`: каждое изображение — нейтральный прямоугольник
с заливкой роли surface из variables (не случайный серый), с подписью-описанием
ассета из поля «Ассеты» content-doc (сюжет, стиль, формат). Плейсхолдер держит
реальные пропорции будущего ассета. Описание желаемого ассета продублировано
в worklog. Вставлять стоковые/сгенерированные картинки в v1 запрещено.

## Уроки прогона dk-sabi (обязательные правила)

### FILL-ребёнок в HORIZONTAL-контейнере требует `primaryAxisSizingMode='FIXED'`

Горизонтальный autolayout-ряд, который должен занимать ширину родителя, задавать как
`layoutSizingHorizontal='FILL'` (или FIXED от ширины родителя) **и** `primaryAxisSizingMode='FIXED'`.
При `primaryAxisSizingMode='AUTO'` контейнер хагает ширину по контенту — а FILL-дети внутри
схлопываются (колонки в ~1px, карты-сетки не дотягивают до правого края). Ловится метаданными
(ширина ряда < ширины родителя) и рендером. Это НЕ то же, что «FILL-в-hug схлопывает текст»
(§ уроки yoga в `figma-library-rules.md`): там схлопывается текстовый узел, здесь — весь ряд.

### `resize()` сбрасывает режимы autolayout

После `node.resize(w,h)` переустанавливать `primaryAxisSizingMode` / `counterAxisSizingMode`
(и при необходимости `layoutSizing*`) — resize возвращает их в FIXED. Симптом: HUG-контейнер
после resize застревает фиксированной высотой (напр. h=10) и перестаёт хагать контент.

### Высоту карт на мобиле не фиксировать — HUG

Мобильные инстансы карточек с переменным по длине текстом делать `layoutSizingVertical='HUG'`
(+ `primaryAxisAlignItems='MIN'`, положительный itemSpacing вместо SPACE_BETWEEN). Захардкоженная
высота обрезает длинные описания. Фикс-высота уместна только там, где несёт смысл (напр. ровные
ступени десктоп-лестницы), — и такие места проверять на самом длинном тексте.

### Грузить ВСЕ шрифты диапазонов перед override rich-text

Перед записью в текст с покомпонентными стилями (Quote с курсивным акцентом, hero-заголовок
с золотым курсивом) грузить не только базовый шрифт, но и стили диапазонов
(`Cormorant Garamond Medium Italic` и т.п.). Иначе `use_figma` падает атомарно (скрипт не создаёт
ничего) на первом же `set_characters`. При смене текст-стиля узла с rich-text — переустанавливать
range-переопределения (шрифт/заливку акцента) после `setTextStyleIdAsync`.

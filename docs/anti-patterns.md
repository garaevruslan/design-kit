# Каталог анти-паттернов AI-дизайна

Чек-лист «AI-tells» — визуальных признаков того, что макет сгенерирован моделью «из
памяти», а не собран из системы. Применяется в верификации (слой 2, `docs/verification.md`)
и как самопроверка в момент изобретения секции (фаза 5).

Каталог — сжатая адаптация списка AI-tells из
[taste-skill](https://github.com/Leonxlnx/taste-skill) (MIT, © 2026 Leonxlnx),
оставлены только пункты, проверяемые на статичном макете.

## Область действия: референс побеждает

Чек-лист применяется **только к тому, что агент изобрёл сам** — секциям с источником
композиции `invented` (`composition-cascade`, ступень 3) и к контенту,
сгенерированному из брифа.

Если паттерн пришёл из референса (ступени 1–2 каскада) — он **легален** по
`reference-source-of-truth`: комплект воспроизводит систему референса, а не судит её.
В verification-report такой случай идёт максимум warning-пометкой «унаследовано из
референса», не блокирует гейт (`no-invented-ai-tells`).

Смысл: комплект защищает от отсебятины модели, а не «улучшает» референс по своему
вкусу. Источник истины — референс.

## Чек-лист (для invented-секций и сгенерированного контента)

### Композиция и структура

- [ ] **Три одинаковые карточки в ряд** — равные колонки как единственный ответ на
  «три штуки». Изобретено → предпочесть bento/зигзаг/асимметрию под реальный вес контента.
- [ ] **3+ zigzag-ряда подряд** (текст-слева-media-справа, зеркально, повтор) —
  монотонный «AI-лендинг». Разбавить другой композицией.
- [ ] **Повтор одного layout-семейства** во всех секциях — нет ритма страницы.
- [ ] **Bento не по контенту** — сетка ячеек, не совпадающая с числом/весом элементов
  (пустые или переполненные клетки ради красивой решётки).
- [ ] **Hero не влезает в первый экран** — оффер и CTA уехали под сгиб.
- [ ] **Длинный список как голый `<ul>`** там, где просится карточки/табы/аккордеон.

### Типографика

- [ ] **Serif «для премиальности»** без опоры на референс — самый частый AI-tell.
  Serif допустим, только если он есть в референсе или контент реально editorial/luxury.
- [ ] **Перенос строки в кнопке** — лейбл CTA не влезает в одну строку на десктопе.
  Сократить лейбл (макс 3 слова) или расширить кнопку.
- [ ] **Заголовок-простыня** — hero-heading длиннее ~8 слов / 2 строк.

### Секционные клише

- [ ] **Eyebrow над каждой секцией** — надстрочная мини-метка как рефлекс. Лимит:
  не чаще чем 1 на 3 секции.
- [ ] **«Scroll ↓» в hero** — пользователь и так знает, что скроллить.
- [ ] **Версия/бейдж в hero** (`v0.6`, `BETA`) без явного повода (лаунч).
- [ ] **Логотипы клиентов с подписями-ярлыками** (`Acme · hosting`) — logo-wall = только
  логотипы, без текстовых довесков.
- [ ] **Больше одного marquee** (бегущая строка) на странице.

### Цвет и форма

- [ ] **Смена акцентного цвета по ходу страницы** — один акцент на весь макет
  (пересекается с `no-detached-values`: цвета из ролей tokens.json).
- [ ] **Разнобой скруглений** — кнопки pill, карточки sharp, инпуты soft без системы.
  Один режим corner-radius на проект (или задокументированное правило).
- [ ] **Кнопка без контраста** — текст на кнопке не читается (WCAG < 4.5:1); ghost-кнопка
  на фото без подложки.

## Как фиксировать

Найденный на invented-секции пункт → расхождение в verification-report (степень как в
`docs/verification.md`: нарушение композиции/иерархии = major, деталь = minor).
Унаследованный из референса → warning-строка «reference-inherited», без блокировки.

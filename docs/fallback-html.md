# Запасной путь: HTML-прототип без Figma MCP

Этот док — для оператора без доступа к Figma MCP. Он заменяет фазы 4–6 основного
пути HTML-эквивалентом. Все правила контракта действуют без ослаблений; артефакты
проекта идентичны основному пути. Итог запасного пути — не поставка, а полуфабрикат:
проекцию в Figma выполняет оператор с доступом (см. «Передача» ниже).

## Фазы 0–3 — без изменений

Reference Study, tokens.json, design-system.md, content-doc.md и гейты 1–2 не требуют
Figma и выполняются по обычным докам (`docs/workflow.md`). `tokens-before-pixels`
действует и здесь: до утверждённого tokens.json HTML не собирается.

## Фаза 4-fb: прототип вместо библиотеки

Выход — единый HTML-файл или маленький статический проект в `project/prototype/`
(например `index.html` + `tokens.css` + `components.css`; без сборщиков и фреймворков).

### CSS custom properties = variables

Кастомные свойства генерируются 1:1 из tokens.json — те же имена, что получили бы
variables в Figma: `--color-bg`, `--color-text-primary`, `--font-size-h1`,
`--space-md`, `--radius-card`, `--shadow-elevated` и т.д. Если tokens.json содержит
темы light/dark — вторая тема через `[data-theme="dark"]` или
`@media (prefers-color-scheme: dark)` с переопределением тех же свойств.

Правила зеркалят шаг 1 фазы 4: ни одного свойства мимо tokens.json, ни одного
ключа tokens.json без свойства, имена 1:1.

### CSS-классы = компоненты

Каждый будущий Figma-компонент — CSS-класс с тем же именем (в kebab-case):
`Button/Primary` → `.button-primary`, `Card/Feature` → `.card-feature`,
`Section/Hero` → `.section-hero`. Варианты — модификаторы: `.button-primary--sm`,
`.button-primary--disabled`; hover — через `:hover`.

План библиотеки записывается в worklog ДО вёрстки — так же, как в
`docs/figma-library-rules.md`, включая маппинг на reference-inventory.

### Страницы

Страницы-секции собираются по content-doc.md. Композиция каждой секции — по
`composition-cascade`, источник фиксируется в worklog. Изображения — плейсхолдеры
(`placeholders-for-assets`).

### Адаптив

Десктоп + мобайл через media queries по брейкпоинтам из tokens.json (брейкпоинты —
единственные «сырые» числа, допустимые в `@media`, поскольку CSS не позволяет
var() в media query; их происхождение — tokens.json, это фиксируется комментарием).

### Правила контракта в HTML-терминах

| Правило | В прототипе означает |
| --- | --- |
| `instances-only` | Разметка секций переиспользует классы-компоненты. Нужен новый паттерн → сначала класс в components.css (+ worklog), потом использование. Инлайн-стили запрещены. |
| `no-detached-values` | В CSS-значениях — только `var(--...)`. Никаких магических чисел, hex-цветов, px-отступов в правилах классов. Исключения — поимённо в worklog. |
| `reference-source-of-truth` | Ничего «на глаз» с эталонных скриншотов — только tokens.json. |
| `worklog-required` | Decision trail ведётся так же; чек-лист самопроверки — по аналогии с фазой 4. |

## Фаза 6-fb: верификация в браузере

Те же три слоя `docs/verification.md`, средства другие:

1. **Аудит** — вместо get_variable_defs: grep по CSS на значения вне `var(--...)`
   (hex, rgb, px в декларациях), проверка полноты секций против content-doc,
   совпадения текстов, отсутствия инлайн-стилей. Найденное сверяется с
   «Утверждёнными исключениями» worklog.
2. **Скриншот-сверка** — открыть прототип в браузере, снять скриншоты каждой секции
   на обеих ширинах (десктопный и мобильный брейкпоинты), сверить с эталонами из
   `project/reference-shots/` по тем же критериям (композиция, иерархия, плотность;
   не пиксель-в-пиксель), расхождения — minor/major.
3. **Отчёт** — `project/verification-report.md` по тому же формату, с пометкой
   `режим: fallback-html`.

Блокировки гейта 4 — те же, что в `docs/verification.md`; гейт 4 здесь принимает
прототип как промежуточную поставку до проекции в Figma.

## Передача оператору с Figma-доступом

Оператор с Figma MCP строит фазы 4–5 обычным путём из:

- **tokens.json** — источник variables (не CSS-файл прототипа: CSS — производная);
- **прототипа** — как композиционного эталона: что за компоненты, как секции
  устроены на обеих ширинах, как ведёт себя адаптив.

**Прототип НЕ импортируется автоконвертером HTML→Figma по умолчанию.** Прототип —
спецификация, а не источник автоимпорта: автоконвертеры дают отвязанные значения,
absolute-позиционирование и мусорные слои, что ломает `no-detached-values` и
autolayout-требования. Автоимпорт допустим только как черновик с последующей полной
нормализацией под `docs/figma-library-rules.md` (variables, привязки, autolayout,
имена, варианты) — и такое решение фиксируется в worklog с мотивировкой.

Worklog при передаче не начинается заново — продолжается тот же
`project/worklog.md`, с записью о смене оператора и режима доступа в шапке.

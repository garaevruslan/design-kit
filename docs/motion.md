# Моушен: анимации как поставка

Комплект добавляет моушен, не превращаясь в генератор фронтенда. Действуют правила
`motion-spec-required`, `motion-motivated`, `motion-observed-classified`, `motion-reduced`.

## Что считается поставкой

| Путь | Поставка по моушену |
| --- | --- |
| все пути | **motion-spec.md** — документ: какая секция каким паттерном анимируется и зачем |
| `fallback-html` | motion-spec **+ живой код**: vanilla GSAP (+ScrollTrigger) через CDN в `index.html` |
| `figma-mcp`, `pencil` | только motion-spec (их движки анимации не входят в скоуп) |

GSAP — vanilla-библиотека, React не нужен: комплект поставляет макеты, а не
приложения. React-обёртка GSAP понадобилась бы только React-проекту, которого в
поставке нет. В HTML-пути GSAP подключается через CDN в прототипе — в сам комплект
никакие зависимости не добавляются.

**Нет моушена — тоже поставка.** Если анимаций в проекте осознанно нет, motion-spec.md
состоит из одной строки: «статический проект, причина: …». Пустой файл без причины =
фаза не сдана (`motion-spec-required`).

## Откуда берётся содержание: три уровня достоверности

Наблюдать «как сайт анимируется» и переносить это в значения — ненадёжно. Поэтому
источник моушена разведён на три уровня, зеркально паре `extraction-css` /
`extraction-vision`. Уровень фиксируется у каждой записи motion-spec.

### Уровень A — детерминированное чтение (не наблюдение)

С живого референса читается CSSOM — это чтение кода, той же природы и надёжности,
что извлечение цветов, а не «на глаз»:

- `transition-*` (property, duration, timing-function, delay) с элементов;
- `@keyframes` и `animation-*` из стайлшитов;
- правила `:hover` / `:focus` — **прямо из `cssRules`, наводить курсор не нужно**;
- `position: sticky | fixed` (кандидаты на pin-паттерны);
- детекция подключённых библиотек: `window.gsap`, `ScrollTrigger`, `window.Lenis`,
  атрибуты `[data-aos]`, признаки Framer Motion.

Отсюда берутся **реальные длительности и easing референса**. Confidence: `high`.
Скрипт-снятие — в `docs/extraction-css.md`, раздел «Моушен».

### Уровень B — классификация поведения

Программный скролл с сэмплированием `transform`/`opacity` ключевых секций. Результат —
**не точные значения, а классификация**: «секция N ведёт себя как sticky-stack /
horizontal-pan / reveal». Confidence: `medium`, пометка обязательна.

Выдумывать точные параметры из наблюдения запрещено (`motion-observed-classified`):
классификация приходит из уровня B, а числа (длительность, easing, дистанция) — из
уровня A или из дефолтов каталога. Так агент не притворяется, что измерил
непокадрово то, что измерить не может.

### Уровень C — изобретение

Vision-путь (референс — картинки, моушен нечитаем) или секции, у которых в референсе
анимации нет. Паттерн выбирается из каталога `library/motion/` по правилу мотивации
(ниже) и помечается «изобретено».

**Против повторов из проекта в проект:** каталог растёт через harvest (как скелеты
секций), а параметры даже одинакового паттерна берутся из уровня A конкретного
референса — длительности и easing разные, «почерк комплекта» не торчит.

## Правило мотивации (`motion-motivated`)

Каждая запись motion-spec обязана отвечать, ЧТО анимация коммуницирует:

- **иерархия** — направляет внимание на главное;
- **storytelling** — раскрывает контент в осмысленной последовательности;
- **feedback** — ответ на действие пользователя;
- **изменение состояния** — показывает, что что-то поменялось.

«Красиво» / «сейчас так модно» — не причина. Запись без мотивации не проходит гейт 4.
(Правило адаптировано из taste-skill, MIT.)

## Каталог `library/motion/`

Паттерны моушена — как скелеты секций: анатомия + канонический GSAP-скелет + типовые
ошибки, без привязки к проекту. Стартовый состав:

- `sticky-stack` — карточки прилипают и складываются при скролле;
- `horizontal-pan` — вертикальный скролл превращается в горизонтальный пан;
- `reveal-rise` — секция проявляется при входе во viewport;
- `stagger-children` — дети секции появляются каскадом.

Пополнение — только через harvest (`harvest-is-curated`). Формат — `library/motion/README.md`.

## Технические запреты (HTML-путь, из taste-skill)

- **Бан** `window.addEventListener("scroll", …)` для анимаций — перерисовка на каждый
  фрейм. Скролл-триггеры только через `ScrollTrigger`.
- `prefers-reduced-motion` **обязателен** (`motion-reduced`): всё выше простых hover
  схлопывается в статику. Проверяется на гейте 4.
- Максимум один pin-паттерн (`sticky-stack` / `horizontal-pan`) на страницу.
- Один тайминг-язык на проект: длительности и easing — из группы `motion` tokens.json
  (см. ниже), а не произвольные числа в каждой анимации.

## Токены моушена (опционально)

Если проект анимируется, в `tokens.json` появляется опциональная группа `motion`:
шкала длительностей и easing (см. `docs/tokens-format.md`, раздел «motion»).
Заполняется значениями уровня A или дефолтами каталога. Группа опциональна:
статический проект валиден без неё, старые проекты не ломаются.

## Чек-лист выхода (в рамках гейта 4)

- [ ] motion-spec.md есть (или явная строка «статический проект, причина»)
- [ ] у каждой записи — уровень достоверности (A/B/C) и источник
- [ ] у каждой анимации — мотивация (иерархия/storytelling/feedback/состояние)
- [ ] значения не выдуманы из наблюдения (числа из уровня A или дефолтов каталога)
- [ ] HTML-путь: нет scroll-listener'ов, есть prefers-reduced-motion, ≤1 pin на страницу
- [ ] длительности/easing — из группы motion tokens.json (если моушен есть)

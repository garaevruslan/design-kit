# Правила фазы 6: верификация

Три слоя приёмки перед гейтом 4: машинный аудит → скриншот-сверка → отчёт человеку.
Слои выполняются строго по порядку: нет смысла сверять скриншоты макета, который
не прошёл аудит привязок. Применяемые правила: `no-detached-values`,
`composition-cascade`, `worklog-required`, `gates-are-blocking`.

Объём проверок определяется tier'ом изменения (таблица в DESIGN-CONTRACT.md).
Первая поставка и пересдача = Tier 4 = полная фаза 6, все три слоя, все страницы.

## Слой 1 — машинный аудит

Инструменты: дамп дерева + офлайн-аудит (ниже). Перед вызовом `use_figma` скилл
`figma-use` обязателен.

**Порядок: дамп → скрипт → таблица находок.**

1. Снять дамп: `use_figma` с телом `scripts/figma/dump-tree.js` (в файле настроить
   `ROOT_ID` и `PAGE`). Снимать по одному фрейму страницы за вызов и склеивать —
   полная страница макетов упрётся в лимит ответа. Результат — в
   `project/figma-dump.json`.
2. Прогнать `node scripts/audit-figma.mjs project/figma-dump.json --worklog
   project/worklog.md --tokens project/tokens.json`. ERROR исправляются, дамп
   снимается заново, аудит перегоняется.

Почему через диск, а не живыми вызовами: аудит становится воспроизводимым,
диффается между итерациями (видно, что исправлено) и перепроверяется без сети.

Почему Plugin API, а не read-инструменты (проверено 2026-07-21): `get_metadata`
отдаёт только структуру и геометрию; `get_variable_defs` — плоский набор
переменных поддерева, он не говорит, какой узел какую использует, и **не
показывает непривязанное** — а правилу нужно именно непривязанное. Привязки на
уровне узла (`paint.boundVariables.color`, `node.boundVariables`) доступны только
через `use_figma`.

**Слой 1 не скоупится источником композиции.** Композиция секции может прийти из
референса — значения обязаны прийти из tokens.json всегда
(`reference-source-of-truth`). Скоупится только каталог анти-паттернов, слой 2.

Проверки:

1. **Нет отвязанных значений.** По каждой странице и каждому компоненту: все fills,
   шрифты, отступы, радиусы, тени привязаны к variables/стилям
   (`get_variable_defs` + `get_design_context`). Каждое найденное отвязанное значение
   сверяется со списком «Утверждённые исключения» в worklog:
   - есть в списке → OK, отмечается в отчёте;
   - нет в списке → **ERROR**.
2. **Полнота секций.** Каждая секция из content-doc.md присутствует в макетах
   (desktop и mobile). Отсутствующая секция → **ERROR**.
2а. **Полнота поставки: фреймы лежат на целевой странице.** Проверять не наличие
   узла по ID, а **состав целевой страницы**: перечислить `page.children` и сверить
   с ожидаемым списком «страница × брейкпоинт» из content-doc. Фрейм, который
   существует и рендерится, но лежит на другой странице файла (типовая причина —
   `clone()` без `setCurrentPageAsync`, см. `assembly-rules.md`), в поставку **не
   входит** → **ERROR**. Заодно проверить обратное: на целевой странице нет
   посторонних/exploration-фреймов, а на замороженных страницах (архив, чужие
   макеты) не появилось узлов текущего прогона.
   Поймано на dk-sabi: два mobile-фрейма оказались на замороженном «Архиве»;
   аудит по ID был чист, поставка — неполной, дефект нашёл человек на приёмке.
   Формулировка правила: **«узел существует» ≠ «узел в поставке»**.
3. **Покрытие inventory.** Каждый паттерн reference-inventory, заявленный в плане
   библиотеки как реализуемый, реализован компонентом/секцией. Незакрытый
   заявленный паттерн → **ERROR** (либо снятие с плана через worklog-запись
   с согласия человека).
4. **Autolayout везде.** Фреймы без autolayout вне зафиксированных декоративных
   исключений → **ERROR**.
5. **Тексты.** Тексты макета совпадают с content-doc.md (заголовки, подписи CTA,
   пункты списков). Расхождение → **ERROR**, кроме технических сокращений,
   зафиксированных в worklog (например, обрезка для мобильной версии по решению
   с evidence).
6. **Иконки.** Все иконки — из коллекции (Reicon) одним весом, цвет через роли токенов
   (`icons-from-collection`, `icon-single-weight`, `icon-color-from-roles`). Иконка вне
   коллекции, второй вес или прямой hex цвета → **ERROR** (кроме плейсхолдеров,
   утверждённых на гейте 3). Маппинг семантика → имя Reicon есть в worklog.
7. **motion-spec.** `project/motion-spec.md` присутствует и непуст: у каждой записи —
   мотивация и уровень A/B/C (`motion-spec-required`, `motion-motivated`). Статический
   проект — строка с причиной. Отсутствие/пустой файл → **ERROR**. HTML-путь: есть
   обработка `prefers-reduced-motion`, нет scroll-listener'ов для анимаций
   (`motion-reduced`) → иначе **ERROR**.

8. **Слоп-теллы (машинная часть).** Прогнать `node scripts/lint-slop.mjs <project-dir>` —
   греп-подмножество каталога `docs/anti-patterns.md`. Скрипт сам находит
   `worklog.md` и `tokens.json` рядом; без worklog scoping «референс побеждает»
   не применяется и все находки идут в полной строгости (скрипт об этом
   предупреждает). ERROR = бан на `invented`-секции → исправляется. Пороги и
   находки на `reference`/`library`-секциях — WARN, идут в отчёт как есть.
   Носитель: путь `fallback-html` — напрямую по CSS/HTML; пути `figma-mcp`
   и `pencil` — по дампу дерева. Что скрипт не ловит грепом, он перечисляет
   в конце прогона — эти правила проверяются глазами в слое 2.

Результат слоя — таблица находок: узел/страница, тип проверки, статус (OK / ERROR /
утверждённое исключение). ERROR'ы исправляются, аудит перегоняется. В отчёт идёт
финальный чистый прогон + список исправленного.

## Слой 2 — скриншот-сверка

Для каждой секции с источником композиции `reference` (по таблице «Источники
композиции» в worklog): `get_screenshot` секции макета против эталонного скриншота
из `project/reference-shots/`.

Что сравнивается — и что нет:

| Сравниваем | НЕ сравниваем |
| --- | --- |
| Композиция: расположение блоков, колонки, порядок | Пиксель-в-пиксель совпадение |
| Иерархия: что доминирует, соотношение масштабов заголовок/текст/media | Конкретные тексты и изображения (контент другой — мы собираем ДРУГОЙ сайт) |
| Плотность: воздух, ритм отступов, заполненность | Точные цвета элементов (они из tokens.json, а не с эталона) |

Секции `library` и `invented` со скриншотом-эталоном не сверяются (эталона нет);
они попадают в отчёт списком для приоритетного взгляда человека.

Каждое расхождение фиксируется со степенью:

- **minor** — композиция и иерархия сохранены, отличие в деталях (плотность чуть
  другая из-за объёма контента, элемент перенёсся из-за длины текста);
- **major** — нарушена композиция или иерархия: блоки в другом порядке, доминанта
  сместилась, секция читается иначе, чем эталон.

Формат записи расхождения: секция, степень, описание, причина/мотивировка
(если известна), предлагаемое действие (исправить / оставить с объяснением).

### Анти-паттерны AI-дизайна (`no-invented-ai-tells`)

Для `invented`-секций и сгенерированного из брифа контента — прогнать каталог
`docs/anti-patterns.md` целиком, сверху вниз: баны → системные → флаги → копирайт.

Область действия — **только изобретённое**. Паттерн, унаследованный из референса
(`reference`- и `library`-секции каскада), легален по `reference-source-of-truth`:
в отчёт идёт warning-строкой «reference-inherited», гейт не блокирует.

Степень расхождения — по severity каталога: **ban → major, system → minor,
flag → warning**. Формат строки находки: `T-номер · секция · где · предлагаемый фикс`.

Находка гасится, если паттерн есть в списке «Утверждённые исключения» worklog — том же,
которым гасятся находки слоя 1 (второй список не заводится). Числовые пороги каталога —
всегда WARN, не ERROR: диапазоны задаёт референс.

В отчёт обязательна группа **«чисто по»** — перечисление проверенных групп каталога
без находок. Без неё непонятно, прогонялся каталог целиком или выборочно.

## Слой 3 — отчёт человеку

Файл `project/verification-report.md`, на русском. Структура:

```markdown
# Verification Report — <проект>

Дата: ... Tier: ... Прогон: первичный | после исправлений N

## Сводка аудита
Страниц проверено: ... Компонентов: ...
ERROR найдено/исправлено: .../...
Отвязанных значений вне исключений: 0 (обязательно)
Утверждённых исключений подтверждено: ...

## Расхождения скриншот-сверки
| Секция | Степень | Описание | Мотивировка | Действие |
| --- | --- | --- | --- | --- |

## Анти-паттерны (только invented-секции)
| T-номер | Секция | Где | Степень | Предлагаемый фикс |
| --- | --- | --- | --- | --- |

Чисто по: <перечисление проверенных групп каталога без находок>

## Invented-секции (смотреть в первую очередь)
- <секция>: краткое описание композиционного решения, ссылка на worklog-запись

## Известные компромиссы
- <компромисс>: причина, что потребуется для устранения
```

Отчёт предъявляется на гейте 4 вместе с макетами. Финальное слово — глаз человека.

## Что блокирует гейт 4, а что нет

**Блокирует** (гейт не предъявляется, пока не устранено):

- любой незакрытый ERROR слоя 1 (отвязанное значение вне исключений, пропавшая
  секция, незакрытый заявленный паттерн, фрейм без autolayout, расхождение текста,
  иконка вне коллекции / второй вес / hex-цвет иконки, отсутствующий или пустой
  motion-spec, немотивированная анимация, HTML без prefers-reduced-motion);
- major-расхождение слоя 2 без объяснения: либо исправить, либо дать мотивировку
  в отчёте и получить на неё явное согласие человека в рамках гейта;
- отсутствующий или пустой verification-report;
- worklog без verification note фазы 6 (`worklog-required`).

**Не блокирует** (идёт в отчёт, решает человек):

- minor-расхождения с мотивировкой;
- major-расхождение, явно вынесенное в отчёт с мотивировкой и вариантами —
  человек решает на гейте (принять / вернуть в работу);
- известные компромиссы, зафиксированные в отчёте;
- invented-секции сами по себе (это не дефект, а зона приоритетного внимания).

Ответ человека на гейте 4 фиксируется в worklog: дата, кто, формулировка.
«Молчание» или «наверное ок» — не приёмка (`gates-are-blocking`).

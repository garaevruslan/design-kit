# Workflow: маршрутизация по фазам

Этот файл — маршрутизатор. Он не заменяет контракт (`DESIGN-CONTRACT.md`), а говорит,
какие доки читать и какие артефакты производить в каждой фазе.

## Определение текущей фазы

Смотри на `project/`:

| Состояние project/ | Текущая фаза |
| --- | --- |
| Пусто или только inputs.md без референсов | Фаза 0 |
| Есть inputs.md с референсами, нет reference-study.md | Фаза 1 |
| Есть study+inventory, нет tokens.json | Фаза 2 |
| tokens.json есть, гейт 1 не зафиксирован в worklog | Гейт 1 (остановка) |
| Гейт 1 пройден, нет утверждённого content-doc.md | Фаза 3 → гейт 2 |
| Гейт 2 пройден, библиотека не построена/не утверждена | Фаза 4 → гейт 3 |
| Гейт 3 пройден, макеты не собраны | Фаза 5 |
| Макеты собраны, нет verification-report.md | Фаза 6 → гейт 4 |
| Гейт 4 пройден | Фаза 7 (harvest) |

Прохождение гейта = запись в worklog: дата, кто утвердил, что именно (формулировка человека).

## Таблица маршрутизации

| Фаза | Читать перед работой | Выход фазы |
| --- | --- | --- |
| 0. Инициализация | DESIGN-CONTRACT.md целиком | project/inputs.md: референсы (URL/файлы), бриф или готовый контент, масштаб проекта, брейкпоинты, версия комплекта (`git describe --tags --always` из репо комплекта) |
| 1. Reference Study | extraction-css.md и/или extraction-vision.md (по формату референса) | reference-study.md, reference-inventory.md, эталонные скриншоты в project/reference-shots/ |
| 2. Дизайн-система | tokens-format.md; для specimen — figma-library-rules.md §specimen | tokens.json (валиден по scripts/validate-tokens.mjs), design-system.md, specimen в Figma (обязателен для гейта 1) |
| 3. Контент | content-doc-format.md | content-doc.md (принятый готовый или сгенерированный из брифа) |
| 4. Библиотека | figma-library-rules.md; при отсутствии Figma MCP — fallback-html.md | Figma variables + компоненты; план библиотеки в worklog |
| 5. Сборка | assembly-rules.md | Страницы в Figma (desktop + mobile), источник композиции каждой секции в worklog |
| 6. Верификация | verification.md | verification-report.md, исправленные расхождения |
| 7. Harvest | library/README.md | Кандидаты-паттерны, после утверждения — файлы в library/ |

Если задача затрагивает несколько фаз (например, правка токенов после сдачи) — читать
доки всех затронутых фаз и классифицировать по tier'ам из контракта (правка токенов = Tier 3).

## Комбинированные ситуации

- **Правки после сдачи.** Структурное (новая секция, смена палитры, новый компонент) —
  через пайплайн с соответствующим tier. Косметика — человек правит руками в Figma;
  агент при следующей регенерации обязан выполнить `manual-edits-respected`.
- **Референс добавили в середине проекта.** Вернуться в фазу 1 для нового референса,
  дополнить inventory; менять tokens.json — только через повторный гейт 1 (Tier 3).
- **Контент готов заранее.** Фаза 3 сводится к валидации формата контент-дока и
  маппингу секций на inventory; гейт 2 остаётся (человек подтверждает маппинг).
- **Нет Figma MCP.** Фазы 0–3 без изменений, дальше fallback-html.md. Артефакты те же.

## Worklog-гейт

Перед сдачей каждой фазы worklog должен содержать для этой фазы:

- запись(и) decision trail: решение, источник/evidence, применённые rule ID,
  отвергнутые альтернативы, проверки, риски;
- verification note (tier, что проверено, что пропущено и почему);
- для гейтов — фиксацию утверждения человеком.

Пустой или формальный worklog = фаза не сдана (`worklog-required`).

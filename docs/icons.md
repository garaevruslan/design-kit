# Иконки: pixel-perfect из коллекции Reicon

Иконки в комплекте — не рисуются ad hoc и не подбираются «на глаз», а извлекаются
из одной коллекции под стиль референса. Действуют правила контракта
`icons-from-collection`, `icon-single-weight`, `icon-color-from-roles`.

Комплект **не хранит SVG у себя**: единый источник `icon-data.json` кэшируется в
проекте и иконки извлекаются по требованию скриптом `scripts/fetch-icons.mjs`.

## Коллекция: Reicon

[Reicon](https://github.com/dqev/reicon) — 2680+ иконок, сетка 24×24, лицензия MIT.
Два веса:

| Вес | Что это | Когда |
| --- | --- | --- |
| **outline** (stroke ≈1.5px) | контурные, тонкая линия | референс с тонкими линейными иконками |
| **filled** | сплошная заливка | референс с плотными «залитыми» иконками |

Одна коллекция на проект, один вес на проект. Смешивать коллекции или подмешивать
иконки из других наборов запрещено (`icons-from-collection`) — это ломает
визуальную консистентность, ради которой существует комплект.

## Поток по фазам

### Фаза 1 — зафиксировать стиль иконок референса

В `reference-study.md` (раздел «Иконки») фиксируется, КАК выглядят иконки референса,
с тем же evidence, что цвета и отступы:

- вес: контурные / сплошные;
- толщина штриха (для контурных): тонкая ≈1.5px / средняя 2px / жирная;
- скругление концов и углов; характерный размер в макете (16/20/24/32).

Отсюда выбирается вес Reicon:

- контурные, штрих ≈1.5px → **outline** (прямое совпадение);
- сплошные → **filled** (прямое совпадение);
- контурные, штрих 2px → **outline** + пометка «ближайшее приближение» в разделе
  «Ограничения» (у Reicon единственный контурный вес — 1.5px);
- vision-путь, стиль иконок неразличим на картинке → **outline** по умолчанию,
  confidence `low`, вынести на гейт 1.

Выбранный вес — решение уровня дизайн-системы, а не отдельной иконки.

### Фаза 2 — иконки как роль системы

В `design-system.md` фиксируются: коллекция (Reicon), вес, размерная шкала иконок
(из spacing/типографики проекта, обычно 16/20/24/32), правило цвета — через роли
токенов (`color.text`, `color.text-muted`, `color.accent`), **никогда** прямым hex
(`icon-color-from-roles`).

### Фаза 3 — семантические имена в контенте

`content-doc.md` называет иконки по смыслу: «иконка расписания», «стрелка перехода»,
«галочка в пункте списка». Имена Reicon (`calendar`, `arrow-right2`) в контент-док
не попадают — это слой реализации, а не контента.

### Фаза 4 — маппинг, извлечение, вставка

1. Для каждой семантической иконки из content-doc подобрать имя Reicon поиском:
   `node scripts/fetch-icons.mjs --search <слово>` (ищет по именам и тегам-описаниям).
2. Записать маппинг **семантика → имя Reicon** в worklog (таблица есть в
   `templates/worklog.md`). Это evidence: почему именно эта иконка.
3. Извлечь SVG выбранного веса:
   `node scripts/fetch-icons.mjs --weight <outline|filled> <name> <name> …`
   → файлы в `project/assets/icons/<name>.svg` (24×24, `fill="currentColor"`).
4. Вставить как вектор в компонент:
   - `figma-mcp` — SVG-нода в слот `icon` компонента; цвет — через привязку к роли;
   - `pencil` — вектор в слот, цвет ролью-переменной;
   - `fallback-html` — inline `<svg>` в разметке, `color: var(--color-…)` на родителе
     (иконка наследует цвет через `currentColor`).

Маппинг иконок входит в приёмку библиотеки на **гейте 3**.

## Механизм: `scripts/fetch-icons.mjs`

Скрипт без зависимостей. При первом вызове скачивает `icon-data.json` (~9 МБ) в
`project/.cache/reicon/` и дальше работает из кэша (в т.ч. офлайн). Кэш —
в `.gitignore` проекта (не коммитится). Два режима:

```bash
# поиск имени под семантику (по именам + тегам):
node scripts/fetch-icons.mjs --search calendar

# извлечение выбранного веса в project/assets/icons/:
node scripts/fetch-icons.mjs --weight outline calendar arrow-right2 user
```

`--weight` обязателен при извлечении (гарантия `icon-single-weight`). Опции:
`--out <dir>`, `--cache <file>`, `--refresh` (перекачать), `--source <url>`.

Кэш переживает даже исчезновение репо Reicon: начатый проект не ломается.

## Правило деградации

Нет точной иконки в Reicon → взять ближайший семантический аналог **из Reicon**.
Подмешать другую коллекцию или нарисовать иконку руками нельзя (`icons-from-collection`).
Аналога нет совсем → плейсхолдер по `placeholders-for-assets` + явная пометка
человеку на гейте 3 (возможно, стоит пересмотреть коллекцию для проекта).

- [ ] Маппинг семантика → имя Reicon в worklog для каждой иконки
- [ ] Все SVG извлечены одним весом в project/assets/icons/

- [ ] Иконок вне Reicon в проекте нет (нет ручной отрисовки, нет других коллекций)

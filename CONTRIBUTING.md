# Как пополнить комплект (harvest через pull request)

Комплект растёт за счёт прогонов: каждый завершённый проект может отдать наверх
паттерны и уроки. Приём вкладов — правило `harvest-is-curated`: мержит только
куратор комплекта.

## Два типа вкладов

### 1. Паттерны (library/)

Скелеты секций (`library/skeletons/`) и схемы компонентов (`library/components/`).

Требования к кандидату (проверяются на ревью):

- **Доказан:** взят из проекта, прошедшего гейт 4 (финальную приёмку), — ссылка
  на worklog проекта в описании PR.
- **Стерилен:** никакого визуального слоя — ни цветов, ни шрифтов, ни размеров
  в px (кроме структурных пропорций). Только анатомия слотов, композиция
  desktop/mobile, роли токенов (имена ролей, не значения).
- **Полон по формату:** все разделы из `library/skeletons/README.md` или
  `library/components/README.md`, включая «Когда НЕ применять» и «Происхождение».
- **Не дубль:** проверь существующие файлы; вариация существующего паттерна —
  это правка его файла (с расширением «когда применять»), а не новый файл.

### 2. Уроки (правки контракта и доков)

Правки `DESIGN-CONTRACT.md` и `docs/*` — отдельным PR (не смешивать с паттернами).
Формат описания обязателен: **какой прогон → какая ошибка случилась → какое
правило её бы предотвратило**. Ссылка на запись «НАХОДКА ДЛЯ КОМПЛЕКТА» в worklog
проекта. Правки контракта меняют поведение агентов у всех пользователей комплекта,
поэтому проходят самое строгое ревью.

## Процесс

1. Заверши прогон (гейт 4 пройден), проведи фазу 7 со своим агентом — он оформит
   кандидатов по форматам.
2. Ветка `harvest/<имя-проекта>` → PR по шаблону.
3. Куратор ревьюит по чек-листу шаблона; замечания правятся в той же ветке.
4. После мержа обнови свой клон (`git pull`) — следующий проект получит новые паттерны.

«Кандидатов нет» — тоже валидный итог прогона; PR в этом случае не нужен.

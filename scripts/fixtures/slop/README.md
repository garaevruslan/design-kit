# Фикстура slop — эталон срабатываний lint-slop.mjs

Намеренно грязный мини-проект. Не образец кода и не пример прогона: каждое правило
здесь существует, чтобы сработал конкретный телл каталога `docs/anti-patterns.md`.

Запуск проверки:

```bash
node scripts/lint-slop.test.mjs     # регрессия: сработало ли всё, что должно
node scripts/lint-slop.mjs scripts/fixtures/slop   # посмотреть находки глазами
```

## Зачем это нужно

Линтер, который ничего не нашёл, неотличим от сломанного: чистый прогон выглядит
одинаково и когда всё хорошо, и когда парсер развалился после правки. Фикстура
даёт эталон — если правило перестало срабатывать, тест скажет.

Проверять сам факт срабатывания недостаточно. У правила бывает несколько веток,
и сломанная ветка может маскироваться исправной: при сломанном разворачивании
`var(--…)` правило T3 всё равно стреляет, но другим сообщением. Поэтому тест
местами сверяет и текст находки, а не только её наличие.

## Что чем ловится

| Файл | Правила |
| --- | --- |
| `prototype/styles.css` | T1, T3, T5, T6, T9, T12 (гасится), T14, T19, T20, T23, T24, T36 |
| `prototype/index.html` | T21, T30, T32, T34 |
| `worklog.md` | scoping «референс побеждает» + гашение по «Утверждённым исключениям» |

Секции размечены в worklog так, чтобы проверялись обе ветки scoping'а: `hero`
и `manifesto` — `reference` (находки понижаются до warning с пометкой
`reference-inherited`), `teachers` — `invented` (полная строгость).

## Правка фикстуры

Правило добавилось в каталог и ловится грепом → добавить сюда пример, который его
поднимает, и строку-проверку в `lint-slop.test.mjs`. Менять существующие правила
«чтобы стало чище» нельзя: файл специально грязный, чистка ломает регрессию.

Ожидаемый итог прогона: **exit 1**, находки по всем правилам выше, `T12` — в группе
«Чисто по» (погашен исключением), а не в находках.

# Схемы компонентов

Схема компонента — его анатомия, а не визуал: что за props, состояния, слоты и какие
**роли** токенов компонент потребляет. Значений токенов здесь нет и быть не может:
визуальный слой всегда приходит из tokens.json текущего проекта. Одна и та же схема
Button в двух проектах даёт две разные кнопки — одинаково устроенные.

Пополнение — только через фазу 7 (`harvest-is-curated`), критерии кандидата —
`library/README.md`. Один компонент = один файл `<id>.md`, имя файла = id.

## Формат файла схемы

```markdown
# <id>

| Поле | Значение |
| --- | --- |
| id | англ. kebab-case, уникален в library/components/ |
| Назначение | одна строка: что компонент делает на странице |
| Происхождение | проект + дата; или "seed (посевной, до первого проекта)" |

## Props / варианты

Английские имена, как в Figma: `size=sm|md|lg`, `variant=primary|secondary`.
Для каждого prop — когда какое значение выбирать.

## Состояния

`state=default|hover|disabled` (+ focus/error где применимо). Для каждого —
что визуально меняется В ТЕРМИНАХ РОЛЕЙ (например: "hover — фон переходит
на роль color.accent-hover"), не в значениях.

## Слоты контента

Что компонент принимает: label, icon, media... Обязательность, ограничения
(например: "label — одна строка, без переноса").

## Роли токенов

Список ролей tokens.json, которые компонент потребляет:
color.accent, color.text-inverse, spacing.sm, radius.control, typography.button...
Только роли — НИКОГДА значения (#hex, px). Если нужной роли в проекте нет,
это сигнал дополнить tokens.json (через Tier 3), а не захардкодить значение.

## Мобильное поведение

Autolayout-поведение (сжатие/перенос/fill) или отдельный вариант
`viewport=desktop|mobile` — и что именно меняется. Обязательный раздел.
```

## Почему только роли, а не значения

Значение (`#4F46E5`, `16px`) принадлежит проекту и живёт в его tokens.json. Роль
(`color.accent`, `spacing.md`) принадлежит паттерну и переживает проект. Схема
со значениями протаскивала бы чужой визуальный слой в новый проект — это нарушает
`reference-source-of-truth` (значения нового проекта приходят из ЕГО референса).
При применении схемы в проекте агент маппит роли схемы на роли актуального
tokens.json; отсутствие роли — повод для решения в worklog, а не для импровизации.

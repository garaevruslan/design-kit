# Накопительная библиотека паттернов

Библиотека — побочный продукт проектов design-kit: с каждым сданным проектом она
растёт и ускоряет следующий. Здесь лежат паттерны без визуального слоя — анатомии
секций и схемы компонентов. Визуальный слой всегда приходит из tokens.json текущего
проекта: один и тот же скелет в двух проектах выглядит по-разному.

## Два слоя

| Слой | Где | Статус |
| --- | --- | --- |
| Данные | `library/` этого репо (skeletons/, components/) | **Источник правды.** Изменения — только через фазу 7. |
| Figma team library | Общий Figma-файл | **Генерируемая проекция данных.** Редактировать руками запрещено. |

Правила проекции:

- Файл-проекция регенерируется агентом из данных `library/` после каждого harvest.
- При регенерации файл **перезаписывается целиком**. Правило `manual-edits-respected`
  на проекцию не распространяется (это его явное исключение, см. DESIGN-CONTRACT.md):
  дифф не снимается, ручные правки не втягиваются — они теряются.
- Хочешь изменить паттерн — меняй данные в репо (через фазу 7 или явную правку
  с утверждением), потом регенерируй проекцию.

## Пополнение: только через фазу 7 (`harvest-is-curated`)

1. По завершении проекта (гейт 4 пройден) агент отбирает кандидатов из сданного
   проекта и предъявляет их человеку списком: что за паттерн, из какой секции/компонента
   проекта, чем полезен будущим проектам.
2. Человек утверждает каждого кандидата отдельно (или отклоняет).
3. Только утверждённые записываются в `library/skeletons/` или `library/components/`
   по форматам соответствующих README. Утверждение фиксируется в worklog проекта.
4. Автоматическое самопополнение запрещено: ни одного файла в `library/` без
   явного «утверждаю» от человека.

«Кандидатов нет» — тоже валидный итог фазы 7, он фиксируется в worklog.

## Что является паттерном-кандидатом

- **Скелет секции** — анатомия без визуального слоя: слоты, композиция desktop,
  поведение mobile. Не «hero сайта X с его цветами», а «hero с текстом слева и
  media справа». Формат — `library/skeletons/README.md`.
- **Схема компонента** — props, варианты, состояния, слоты, роли токенов
  (роли, не значения). Формат — `library/components/README.md`.

Не кандидаты: конкретные цвета/шрифты/тексты, композиции, завязанные на уникальный
контент проекта, одноразовые декоративные решения.

## Критерии качества кандидата

Кандидат предъявляется человеку, только если проходит все три:

1. **Доказан в сданном проекте.** Паттерн реально использован в макетах, прошедших
   гейт 4, — не «идея по ходу работы».
2. **Обобщён от проектных деталей.** Из описания убраны конкретные тексты, значения
   токенов, специфика бренда; остались слоты, структура и роли. Тест: другой проект
   с другим tokens.json может взять паттерн без правок.
3. **Описана мобильная адаптация.** Без описания поведения mobile паттерн неполон
   и в библиотеку не принимается.

## Использование в проектах

Библиотека — второй приоритет каскада `composition-cascade`: нет аналога в
референсе → ищем скелет здесь → нашли → источник композиции секции в worklog
помечается `library` со ссылкой на файл паттерна.

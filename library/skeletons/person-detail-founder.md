# person-detail-founder

| Поле | Значение |
| --- | --- |
| id | person-detail-founder |
| Тип секции | detail-page (полная страница персоны, CMS-шаблон) |
| Происхождение | dk-sabi, 2026-07-15 (референс hollow-template.webflow.io: founder-блок `/about`) |

Скелет **целой страницы**, не одной секции: детальная карточка персоны (преподаватель, мастер,
автор направления), которую открывают из сетки команды. В референсе Hollow отдельной страницы
персоны нет — сетка команды на `/about` не кликабельна; каркас взят из founder-блока той же
страницы и достроен до полноценного шаблона коллекции.

## Анатомия (слоты)

- **hero** (обязательный) — портрет + имя + роль-направление (чип) + опциональный тэглайн в строку.
- **intro** (обязательный) — «кто это»: портрет + многоабзацная проза (founder-блок референса).
- **path-numbers** (опциональный) — 2–4 показателя пути (лет практики, направлений, проведённых
  событий). Блок доверия; при нехватке подтверждённых данных сокращается или скрывается целиком.
- **directions** (опциональный) — чипы направлений/практик, которые ведёт персона.
- **quote** (опциональный) — личная цитата о своём пути/подходе + подпись (аналог FROM FOUNDER).
- **related-events** (обязательный) — события/занятия этой персоны из связи коллекций; **мост к
  конверсии**. Обязателен слот пустого состояния: «сейчас нет открытых потоков» + переход в общее
  расписание.
- **cta** (обязательный) — финальный призыв выбрать событие.

## Композиция desktop

Одна центрированная колонка с крупным вертикальным ритмом. `hero` — портрет в портретной
пропорции (~4:5), под ним имя самым крупным шагом, роль-чип и тэглайн; высота ~100vh опорного
viewport. `intro` — **две колонки**: портрет слева (~1/3), проза справа (~2/3), проза выровнена
влево, остальные секции центрированы. `path-numbers` — цифры в ряд, равными долями. `directions` —
wrapping-ряд чипов. `quote` — центрированная, ограничена мерой текста. `related-events` — карточки
событий в сетку 2–3 в ряд. `cta` — контрастная плашка на всю ширину.

Текстовые блоки ограничены мерой строки (`layout.measure.text`), карточки-ссылки — своей мерой
(`layout.measure.cardCompact`); ограничение задаётся `maxWidth`, не фиксированной шириной.

## Композиция mobile

Всё в один столбец. `hero` — портрет уменьшается, порядок сохраняется. `intro` — двухколонник
складывается в стек: портрет сверху, проза под ним (следить за высотами вложенных контейнеров,
см. `assembly-rules.md` про смену `layoutMode`). `path-numbers` — цифры в вертикальный стек.
`directions` — чипы переносятся (не растягиваются на всю ширину). `related-events` — карточки
в 1 колонку. `cta` — кнопка FILL по ширине.

## Когда применять

- Детальная страница персоны в CMS-каталоге (преподаватели, мастера, спикеры), куда ведут сетка
  команды и упоминания персоны на страницах событий.
- Нужен мост «доверие к персоне → её события»: страница обязана заканчиваться конверсией, а не
  биографией.

## Когда НЕ применять

- Персона одна на весь сайт (основатель) — тогда это блок на странице «О нас»
  (`manifesto-centered` + `split-feature-media`), а не отдельный шаблон.
- У персон нет связанных событий и нечем закрыть `related-events` — останется тупиковая страница.
- Нужен полноценный профиль с портфолио/лентой публикаций — это другой layout (каталог внутри
  страницы, с фильтрами).

# Скелеты секций

Скелет — анатомия секции без визуального слоя: какие слоты есть, как они скомпонованы
на десктопе и что происходит на мобиле. Никаких цветов, шрифтов, конкретных значений —
визуальный слой приходит из tokens.json текущего проекта. Пополнение — только через
фазу 7 (`harvest-is-curated`), см. `library/README.md`.

Один скелет = один файл `<id>.md`. Имя файла = id.

## Формат файла скелета

```markdown
# <id>

| Поле | Значение |
| --- | --- |
| id | англ. kebab-case, уникален в library/skeletons/ |
| Тип секции | hero / features / pricing / testimonials / faq / cta / footer / ... |
| Происхождение | проект + дата, из которых собран; или "seed (посевной, до первого проекта)" |

## Анатомия (слоты)

Список слотов с пометкой обязательный/опциональный: заголовок, подзаголовок,
CTA, media, badge и т.д. Для каждого — назначение в одну строку.

## Композиция desktop

Колонки/сетка, порядок слотов, выравнивание, доминанта. Пропорции — в долях
сетки, не в px.

## Композиция mobile

Что складывается в стек и в каком порядке, что скрывается, что меняет
выравнивание. Обязательный раздел: скелет без него в библиотеку не принимается.

## Когда применять

1–3 пункта: для какого контента/задачи скелет работает.

## Когда НЕ применять

1–3 пункта: где скелет даст плохой результат.
```

Поле «Происхождение» обязательно: оно позволяет вернуться к проекту-источнику
и его evidence, если скелет вызовет вопросы.

# hero-split

| Поле | Значение |
| --- | --- |
| id | hero-split |
| Тип секции | hero |
| Происхождение | seed (посевной, до первого проекта) |

## Анатомия (слоты)

- **eyebrow** (опциональный) — короткая надстрочная метка над заголовком: категория, оффер-тизер.
- **heading** (обязательный) — главный заголовок секции, самый крупный текст страницы.
- **subheading** (обязательный) — подзаголовок: 1–3 строки, раскрывает оффер.
- **cta-primary** (обязательный) — главная кнопка действия.
- **cta-secondary** (опциональный) — вторичное действие: «узнать больше», ссылка на демо.
- **media** (обязательный) — изображение/иллюстрация/скрин продукта; в v1 — плейсхолдер.
- **social-proof** (опциональный) — строка доверия под CTA: логотипы клиентов, рейтинг, счётчик.

## Композиция desktop

Две колонки на всю ширину контентной сетки, вертикальное выравнивание по центру:

- **Левая колонка (~6/12 сетки):** текстовый стек сверху вниз — eyebrow → heading →
  subheading → ряд CTA (primary + secondary в одну строку) → social-proof.
  Выравнивание текста по левому краю.
- **Правая колонка (~6/12 сетки):** media, заполняет колонку по ширине.

Доминанта — heading; media поддерживает, а не конкурирует. Допустимое смещение
пропорций до 7/12 + 5/12 в пользу текста при длинном заголовке.

## Композиция mobile

Складывается в один стек, порядок сверху вниз: eyebrow → heading → subheading →
cta-primary → cta-secondary → media → social-proof.

- Текст остаётся выровненным по левому краю (центрирование — только если это
  системное решение проекта, фиксируется в worklog).
- CTA растягиваются на полную ширину, secondary — под primary.
- media уходит ПОД текстовый блок (оффер и действие — раньше картинки).
- social-proof допустимо сократить (логотипы — в одну строку со скроллом или
  скрыть частично).

## Когда применять

- Продуктовый или сервисный лендинг с одним понятным оффером и визуалом продукта.
- Когда есть внятный media-ассет (скрин, иллюстрация), поддерживающий оффер.
- Когда нужен быстрый первый экран «оффер + действие» без сложной навигации по вариантам.

## Когда НЕ применять

- Оффер сугубо текстовый, media нечем заполнить — плейсхолдер ради плейсхолдера
  ослабит секцию; лучше центрированный текстовый hero.
- Несколько равнозначных продуктов/офферов на первом экране — split-структура
  навязывает одну доминанту.
- Референс проекта диктует другую композицию hero — приоритет у референса
  (`composition-cascade`, ступень 1).

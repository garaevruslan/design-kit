# stagger-children

| Поле | Значение |
| --- | --- |
| id | stagger-children |
| Тип | stagger |
| Мотивация по умолчанию | storytelling (набор элементов собирается по одному) |
| Происхождение | seed (посевной, до первого проекта) |

## Что это

Дети контейнера (карточки features, пункты списка, логотипы) появляются не разом, а
каскадом с небольшим сдвигом по времени. Коммуницирует: это набор равнозначных
элементов, и их количество/ритм считываются через последовательное появление.

## Классификация (уровень B)

Признаки в референсе: группа однотипных детей одного контейнера с одинаковым reveal,
но нарастающей задержкой (`transition-delay` возрастает от элемента к элементу, или
GSAP-stagger).

## Канонический скелет (GSAP, HTML-путь)

Один триггер на контейнер, `stagger` разводит детей по времени.

```js
gsap.from(container.children, {
  opacity: 0,
  y: 16,
  duration: 0.5,        // → var(--motion-duration-fast)
  ease: "power2.out",   // → var(--motion-ease-standard)
  stagger: 0.08,
  scrollTrigger: {
    trigger: container,
    start: "top 80%",
    toggleActions: "play none none none",
  },
});
```

Триггер — контейнер (не каждый ребёнок): каскад запускается по входу группы.

## Типовые ошибки

- Индивидуальный ScrollTrigger на каждом ребёнке вместо одного на контейнере со
  `stagger` — рассинхрон и лишние триггеры.
- Слишком большой `stagger` (> ~0.12с на элемент) при длинном списке — хвост
  появляется мучительно долго.
- Каскад на списке из десятков элементов — воспринимается как лаг, не как приём.

## Reduced motion

Отключается: все дети сразу в финальном состоянии, без сдвига и задержек.

## Когда применять / когда НЕ применять

Применять: ряд из 3–8 карточек features, сетка логотипов, короткий список
преимуществ — где ритм появления подчёркивает «набор».

НЕ применять: единичный элемент (нечего каскадить); длинные списки/таблицы;
контент первого экрана; больше одного заметного каскада на секцию.

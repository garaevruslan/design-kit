# reveal-rise

| Поле | Значение |
| --- | --- |
| id | reveal-rise |
| Тип | scroll-reveal |
| Мотивация по умолчанию | иерархия (секция заявляет о себе при входе во внимание) |
| Происхождение | seed (посевной, до первого проекта) |

## Что это

Секция или блок проявляется при входе во вьюпорт: лёгкий подъём снизу + fade in.
Коммуницирует: контент «прибывает» в момент, когда пользователь до него доскроллил —
мягкий акцент на новом блоке.

## Классификация (уровень B)

Признаки в референсе: элементы стартуют с `opacity: 0` и небольшим `translateY`,
переходят в норму один раз при пересечении вьюпорта (не привязано к скроллу scrub'ом,
срабатывает по триггеру входа).

## Канонический скелет (GSAP, HTML-путь)

Однократный reveal по входу; дистанция подъёма — малый шаг spacing, длительность и
easing — из группы motion токенов.

```js
gsap.from(el, {
  opacity: 0,
  y: 24,
  duration: 0.6,       // → var(--motion-duration-base)
  ease: "power2.out",  // → var(--motion-ease-standard)
  scrollTrigger: {
    trigger: el,
    start: "top 85%",
    toggleActions: "play none none none",
  },
});
```

`toggleActions: "play none none none"` — проигрывается один раз и не откатывается
при обратном скролле (мельтешение раздражает).

## Типовые ошибки

- Reveal на КАЖДОМ элементе страницы — обесценивает приём, страница «дёргается» всю
  прокрутку. Применять к секциям/крупным блокам, не к каждому абзацу.
- Большой `translateY` (>~32px) — контент «прыгает», ощущается медленным.
- Реверс-анимация при обратном скролле — контент моргает; использовать однократный play.

## Reduced motion

Полностью отключается: элементы сразу в финальном состоянии (`opacity: 1`, без сдвига).

## Когда применять / когда НЕ применять

Применять: последовательные контентные секции лендинга, где мягкое проявление задаёт
ритм чтения.

НЕ применять: контент первого экрана (hero виден сразу — reveal прячет оффер);
плотные интерфейсы/дашборды; списки из десятков однотипных элементов.

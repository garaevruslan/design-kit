# Паттерны моушена

Паттерн моушена — анатомия анимации без привязки к проекту: что за движение, что оно
коммуницирует, канонический скелет реализации и типовые ошибки. Конкретные
длительности и easing приходят из группы `motion` tokens.json текущего проекта или из
уровня A его референса (`docs/motion.md`) — здесь их нет.

Пополнение — только через фазу 7 (`harvest-is-curated`), см. `library/README.md`.
Один паттерн = один файл `<id>.md`. Имя файла = id.

Скелеты кода в паттернах — vanilla GSAP (+ScrollTrigger), реализуются в `fallback-html`
пути; для `figma-mcp` и `pencil` паттерн работает как словарь для motion-spec
(классификация поведения секции), код не реализуется.

## Формат файла паттерна

```markdown
# <id>

| Поле | Значение |
| --- | --- |
| id | англ. kebab-case, уникален в library/motion/ |
| Тип | scroll-reveal / pin-scrub / stagger / hover / transition |
| Мотивация по умолчанию | иерархия / storytelling / feedback / изменение состояния |
| Происхождение | проект + дата; или "seed (посевной, до первого проекта)" |

## Что это

Одна-две строки: что за движение и что оно коммуницирует пользователю.

## Классификация (уровень B)

По каким признакам секция референса опознаётся как этот паттерн: sticky/fixed,
характер изменения transform/opacity при скролле. Для motion-spec уровня B.

## Канонический скелет (GSAP, HTML-путь)

Минимальный корректный код через ScrollTrigger. Длительности/easing —
через переменные группы motion токенов, не хардкодом.

## Типовые ошибки

Чем портят этот паттерн (scroll-listener вместо ScrollTrigger, отсутствие pin,
дёрганый scrub и т.д.).

## Reduced motion

Во что схлопывается при prefers-reduced-motion (обязательно — `motion-reduced`).

## Когда применять / когда НЕ применять

1–3 пункта на каждое.
```

Поле «Происхождение» обязательно: позволяет вернуться к проекту-источнику, если
паттерн вызовет вопросы.

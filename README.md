# design-kit

Комплект инструкций для ИИ-агента: **из референса — в дизайн-систему и макеты Figma**.

Проблема, которую решает комплект: ИИ-модель без референса генерирует «усреднённый
вчерашний» дизайн из своей памяти. design-kit вырезает память модели из контура:
каждый цвет, шрифт и отступ извлекается из живого референса, фиксируется как данные
и проверяется машинным аудитом. Агент компонует — но не выдумывает значения.

Дисциплина комплекта построена по образцу [Toolcraft](https://toolcraft.pixelpoint.io/):
контракт с правилами, reference study до пикселей, гейты утверждения человеком,
worklog с decision trail, машинные проверки.

## Как это работает

```
Референс (URL / скриншоты)
  → Фаза 1. Reference Study: извлечение значений из живого сайта
  → Фаза 2. Дизайн-система как данные (tokens.json) + specimen в Figma
      ── ГЕЙТ 1: вы утверждаете систему глазами ──
  → Фаза 3. Структура и контент  ── ГЕЙТ 2 ──
  → Фаза 4. Библиотека компонентов в Figma (variables, варианты, адаптив)  ── ГЕЙТ 3 ──
  → Фаза 5. Макеты страниц из инстансов (desktop + mobile) + motion-spec (GSAP в HTML-пути)
  → Фаза 6. Верификация: аудит привязок + скриншот-сверка + анти-паттерны AI-дизайна
      ── ГЕЙТ 4: финальная приёмка ──
  → Фаза 7. Harvest: паттерны и уроки прогона — в общую библиотеку (PR)
```

Ключевой принцип: **система из референса → свой контент**. Комплект не клонирует
референс — он извлекает его дизайн-язык и собирает на нём ваш сайт.

## Быстрый старт

**Мало опыта с кодом и терминалом?** Иди в [ONBOARDING.md](ONBOARDING.md) —
там путь из двух действий руками (установить Claude Code и вставить один промпт),
всю настройку агент делает сам. Ниже — путь для тех, кому терминал привычен.

Требования:

- ИИ-агент с доступом к файлам и терминалу (Claude Code; подойдёт и другой агент,
  умеющий следовать инструкциям из файлов);
- браузерный MCP для фазы извлечения (chrome-devtools или аналог);
- Node.js (для валидатора токенов и генераторов);
- инструмент фаз 4–6 — по матрице ниже (Figma MCP НЕ обязателен).

## Какой путь выбрать (фазы 4–6)

Фазы 0–3 одинаковы на всех путях. Дальше — три пути; правила контракта и
артефакты идентичны, отличается инструмент (сверено обкаткой трёх исполнений
одного продукта, 2026-07-06):

| | `figma-mcp` | `pencil` | `fallback-html` |
| --- | --- | --- | --- |
| **Что нужно** | тариф Figma с местом редактора (Pro/Edu) + авторизованный Figma MCP | [Pencil](https://www.pencil.dev) — бесплатен в early access; ИИ работает через подписку Claude (Claude Code) | только браузер + Node.js |
| **Платформы** | Figma (облако) | macOS (Apple Silicon/Intel), Windows x64 (ARM64 — скоро), Linux (AppImage/tarball); веб-версии НЕТ; на Windows настройка MCP сложнее — см. ONBOARDING | любые |
| **Результат** | Figma-файл: отраслевой стандарт передачи | .pen-файл — настоящая дизайн-канва (открытый JSON в папке проекта, версионируется git) + export_html/PNG | интерактивный HTML-прототип |
| **Механика системы** | variables + режимы коллекций, вариант-сеты, hover-состояния | $-переменные с осями тем (light/dark, desktop/mobile); вариант-сетов и hover НЕТ | CSS custom properties, media queries, настоящий :hover |
| **Скорость / токены** | самый дорогой (сотни мелких вызовов) | средний (батчи ≤3КБ, скриншоты по одному) | самый быстрый и дешёвый |
| **Зрелость** | зрелый | early access: шероховатости, см. диагностику в pencil-path.md | максимально стабильный |
| **Кому** | результат сдаётся дизайнерам/клиенту в Figma | нужна бесплатная редактируемая канва | быстро увидеть систему глазами; ученикам без тарифов |
| **Док** | docs/figma-library-rules.md + assembly-rules.md | docs/pencil-path.md | docs/fallback-html.md |

Шаги:

```bash
# 1. Клонировать комплект (один раз; обновления — git pull)
gh repo clone garaevruslan/design-kit

# 2. Claude Code: установить скилл
cp -r design-kit/skills/design-kit ~/.claude/skills/design-kit

# 3. Создать проект (каждый новый проект — одной командой)
node design-kit/scripts/create-project.mjs my-landing
```

Дальше: заполни `my-landing/project/inputs.md` (референс + бриф) и скажи агенту
«продолжаем проект design-kit в my-landing» — или сразу «новый проект design-kit,
референс — <URL>, продукт — <бриф>», тогда агент выполнит шаг 3 сам. Без Claude
Code: попроси агента прочитать `DESIGN-CONTRACT.md` и `docs/workflow.md` и вести
проект по ним. Агент останавливается на гейтах — твоя работа смотреть глазами
и говорить «утверждаю» или давать правки.

Живые примеры: полный прогон — [`examples/yoga-school-demo`](examples/yoga-school-demo)
(путь figma-mcp); те же фазы 4–6 без Figma —
[`examples/opora-pencil`](examples/opora-pencil) и
[`examples/opora-html-fallback`](examples/opora-html-fallback).

## Состав репозитория

| Путь | Что это |
| --- | --- |
| `DESIGN-CONTRACT.md` | Контракт: правила с rule ID, фазы, гейты, tier'ы проверок. Точка входа для агента |
| `docs/` | Правила фаз: извлечение (CSS/vision-путь), формат токенов, контент-док, иконки, моушен, библиотека Figma, сборка, верификация, анти-паттерны, пути без Figma (pencil-path, fallback-html) |
| `templates/` | Шаблоны артефактов проекта (study, inventory, worklog, пример tokens.json) |
| `library/` | **Библиотека паттернов**: скелеты секций, схемы компонентов и паттерны моушена без визуального слоя — растёт с каждым прогоном |
| `scripts/` | validate-tokens.mjs (валидатор: шкалы, роли, WCAG, лицензии, моушен), create-project.mjs (скаффолдер), fetch-icons.mjs (иконки Reicon по требованию), tokens-to-css.mjs и tokens-to-pen-vars.mjs (генераторы переменных для путей fallback-html/pencil) |
| `skills/design-kit/` | Скилл-дирижёр для Claude Code |
| `examples/` | Полные прогоны с артефактами и worklog |
| `CONTRIBUTING.md` | Как отдать паттерны и уроки своего прогона в комплект (PR) |

## Глоссарий

| Термин | Значение |
| --- | --- |
| **Комплект** | Этот репозиторий целиком — процесс + правила + накопленные паттерны |
| **Контракт** | DESIGN-CONTRACT.md; агент обязан его соблюдать, правила имеют rule ID |
| **Пайплайн** | 7 фаз с гейтами, которые агент проходит по контракту |
| **Гейт** | Блокирующая остановка: агент не продолжает без явного «утверждаю» |
| **Артефакты проекта** | Содержимое `project/` конкретного прогона: study, tokens.json, worklog… |
| **Библиотека паттернов** | `library/` комплекта: анатомии секций/компонентов, переносятся между проектами |
| **Компоненты проекта** | Страница «02 Components» в Figma-файле проекта: кожа конкретного проекта, НЕ переносится |
| **Specimen** | Страница-образец системы в Figma — обязательная часть гейта 1 |
| **Слоты (ассетов)** | Плейсхолдеры картинок в макетах с ТЗ на реальный ассет (в worklog) |
| **Harvest** | Фаза 7: паттерны и уроки прогона отдаются в комплект (владелец — напрямую, ученик — через PR) |

## Каждый прогон делает комплект лучше

Ошибки прогонов превращаются в правила контракта. Первый же прогон дал пять правок
(обязательный specimen, проверка глифов шрифтов под язык контента, белая заливка
фреймов Figma и др.) — см. записи «НАХОДКА ДЛЯ КОМПЛЕКТА» в worklog примера.
Твои находки жду в PR — процесс в `CONTRIBUTING.md`.

# design-kit: дирижёр

Ты работаешь по комплекту design-kit. Твоя роль — провести проект через фазы контракта,
не пропуская гейты. Ты не имеешь права заменять процесс комплекта импровизацией.

## Шаг 1. Найди комплект и проект

1. Найди клон репозитория design-kit (признаки: `DESIGN-CONTRACT.md` + `library/` +
   `docs/workflow.md` в корне). Порядок поиска: текущая папка → родительские →
   спроси путь у пользователя. Запомни путь как «репо комплекта».
2. Если пользователь работает в папке проекта (есть `DESIGN-CONTRACT.md` и `project/`,
   но НЕТ `library/`) — это проект; репо комплекта всё равно найди (для библиотеки
   паттернов и harvest).
3. Прочитай `DESIGN-CONTRACT.md` ЦЕЛИКОМ и `docs/workflow.md`. Это обязательный
   preflight — без него не планируй и не редактируй ничего.

## Шаг 2. Инициализация нового проекта (если проекта ещё нет)

1. Спроси у пользователя папку проекта (или согласуй создание новой).
2. Выполни скаффолдер: `node <репо-комплекта>/scripts/create-project.mjs <папка>` —
   он скопирует снимок комплекта, создаст `project/` (inputs.md с версией
   комплекта + worklog.md из шаблона). Библиотека `library/` намеренно не
   копируется — читай её из репо комплекта (она общая и растёт между проектами).
3. Заполни `project/inputs.md` данными от пользователя: референсы (URL/файлы),
   бриф или готовый контент, масштаб (страницы), брейкпоинты. Чего не хватает —
   запроси.

## Шаг 3. Определи фазу и работай по маршрутизации

Определи текущую фазу по таблице в `docs/workflow.md` (по состоянию `project/`).
Прочитай доки, назначенные фазе. Выполняй фазу, производя её артефакты по шаблонам.

Жёсткие правила ведения (дублируют контракт — нарушение недопустимо):

- **Гейты блокируют.** В конце фаз 2, 3, 4 и 6 остановись, предъяви артефакты,
  запроси явное утверждение. Продолжать без «утверждаю» нельзя
  (`gates-are-blocking`). Утверждение зафиксируй в worklog. Гейт 1 предъявляется
  ТОЛЬКО вместе со specimen в Figma (см. контракт, `tokens-before-pixels`).
- **Никаких значений из памяти.** Цвета/шрифты/отступы — только из извлечённых данных
  или tokens.json (`reference-source-of-truth`, `tokens-before-pixels`).
- **Worklog по ходу, не задним числом** (`worklog-required`).
- **tokens.json валидируй скриптом** `node scripts/validate-tokens.mjs project/tokens.json`
  до предъявления на гейт 1.
- **Перед use_figma** загрузи скиллы figma-use (и figma-generate-library /
  figma-generate-design по задаче). Если Figma MCP не авторизован — сообщи пользователю
  и предложи либо остановиться на фазе 3, либо перейти на запасной путь
  `docs/fallback-html.md`.
- **Правки в существующем проекте**: классифицируй по tier'ам контракта; перед
  регенерацией Figma-файла выполни `manual-edits-respected` (дифф против данных).

## Шаг 4. Завершение (фаза 7 — harvest, два режима)

После гейта 4 предложи пользователю кандидатов в накопительную библиотеку
(скелеты секций, схемы компонентов — по форматам `library/*/README.md`) и находки
для правил комплекта (записи «НАХОДКА ДЛЯ КОМПЛЕКТА» из worklog).

Спроси у пользователя его роль:

- **Владелец комплекта** (пишет в основной репозиторий): утверждённые паттерны
  записывай напрямую в `library/` репо комплекта, правки правил — в контракт/доки;
  закоммить с осмысленным сообщением.
- **Ученик / контрибьютор** (работает на клоне): создай ветку
  `harvest/<имя-проекта>`, положи кандидатов в `library/`, оформи pull request
  по `CONTRIBUTING.md` (шаблон PR заполняется автоматически). Правки правил —
  отдельным PR с описанием «прогон → ошибка → правило».

Если кандидатов нет — зафиксируй это в worklog явно.

## Долг честности

Не выдавай фазу за завершённую, если проверки не пройдены, пропущены или заблокированы.
Заблокирован (нет доступа, нет данных) — остановись и скажи, что нужно от пользователя.

# Пример: opora-pencil

Обкатка пути **`pencil`** (docs/pencil-path.md) — фазы 4–6 того же продукта,
что в `examples/yoga-school-demo`, в Pencil 1.1.68 БЕЗ Figma MCP. Одно из трёх
исполнений «Опоры» для сравнения путей (Figma / HTML / Pencil, 2026-07-06).

- **Продукт и артефакты фаз 1–3:** переиспользованы из
  `../yoga-school-demo/project/` (утверждены гейтами 1–2 исходного прогона;
  здесь не дублируются).
- **Результат:** `project/opora-yoga-demo.pen` — открытый JSON (v2.14):
  77 переменных с осями тем mode/viewport, специмен, 12 базовых + 18
  секционных компонентов, страницы home/desktop-1440 и home/mobile-390.
  Открывается в Pencil; руками/агентом файл НЕ редактировать — только
  инструменты Pencil MCP.
- **Гейты 3–4:** приняты 2026-07-06 («Приемка пройдена», без правок).

## Порядок чтения

1. `project/inputs.md` — режим, происхождение артефактов
2. `project/pencil-mapping.md` — соответствие «гайдлайны/инструменты Pencil ↔
   доки design-kit» + 15 находок обкатки (легли в docs/pencil-path.md)
3. `project/worklog.md` — decision trail: инфраструктурные обходы подключения,
   план библиотеки, исключения аудита, 5 «НАХОДОК ДЛЯ КОМПЛЕКТА»
4. `project/verification-shots/` — специмен, компоненты, все секции и страницы
   в обеих ширинах (get_screenshot)
5. `project/export-html/home-desktop-1440.html` — export_html как deliverable
6. `project/verification-report.md` — аудит по JSON, сверка, компромиссы пути

## Чему учит пример

Как контракт ложится на Pencil: оси тем = режимы Figma-коллекций,
reusable/ref = компоненты/инстансы (вариант-сетов нет — конвенция имён),
аудит `no-detached-values` по JSON документа, snapshot_layout ловит
переполнения до скриншотов. И диагностика подключения MCP — самая частая
причина «ничего не работает» на этом пути.

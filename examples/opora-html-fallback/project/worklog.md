## Decision Trail

### [Фаза 0] Происхождение артефактов: переиспользование фаз 1–3 исходного прогона

- **Дата:** 2026-07-06
- **Запрос / задача:** обкатать HTML-путь (docs/fallback-html.md) на том же продукте
  «Опора» для сравнения трёх исполнений (Figma / HTML / Pencil); фазы 1–3 не
  пересобирать.
- **Решение:** проект скаффолжен `scripts/create-project.mjs` (комплект
  v1.0-3-g5ceb730). Артефакты фаз 1–3 скопированы 1:1 из
  `design-kit/examples/yoga-school-demo/project/`: reference-study.md,
  reference-inventory.md, tokens.json, design-system.md, content-doc.md.
  Все они утверждены гейтами 1–2 исходного прогона (worklog примера,
  2026-07-05). Эталонные скриншоты `reference-shots/` в examples не включены
  (47МБ) — для скриншот-сверки фазы 6 эталоны будут пересняты с живого
  референса точечно (сайт живой, css-path).
- **Источник / evidence:** указание оператора (сессия 2026-07-06);
  examples/yoga-school-demo/project/worklog.md (таблица гейтов).
- **Применённые rule ID:** `worklog-required`, `gates-are-blocking` (гейты 1–2
  не проходятся повторно — перенесены с фиксацией происхождения)
- **Отвергнутые альтернативы:** повторное извлечение референса (запрещено
  задачей — артефакты утверждены; пересборка исказила бы сравнение исполнений).
- **Проверки / tier:** Tier 0 (файлы проекта); валидация токенов —
  `node scripts/validate-tokens.mjs project/tokens.json` перед фазой 4-fb.
- **Риски:** отсутствие эталонных скриншотов в examples — компенсируется живым
  референсом; расхождения live-сайта с инвентарём фиксировать как находки.

### [Фаза 4-fb] План библиотеки (ДО вёрстки)

- **Дата:** 2026-07-06
- **Запрос / задача:** зафиксировать состав классов-компонентов до вёрстки
  (зеркало плана библиотеки исходного прогона, масштаб — только лендинг home).
- **Решение:** файлы `project/prototype/tokens.css`, `components.css`,
  `index.html`, `components.html` (превью для гейта 3). Соответствие именам
  Figma-библиотеки исходного прогона (kebab-case по fallback-html.md):
  - **Базовые** (адаптив авто-поведением flex/wrap, если не указано):
    `.button` (Button; state hover через `:hover`; один размер md — sm на
    лендинге не используется) — из buttons-inputs;
    `.badge` (Badge; `--accent` | `--outline`) — из timetable-schedule +
    лаймовые лейблы секций;
    `.input` (Input; `:focus`) — из buttons-inputs + форма футера;
    `.card-class` (Card/Class) — home-classes;
    `.card-teacher` (Card/Teacher, invented: анатомия Card/Class) — сетка home-classes;
    `.card-pricing` (Card/Pricing) — store-pricing;
    `.schedule-cell` (Card/ScheduleCell) — timetable-schedule;
    `.value-item` (ValueItem) — home-about;
    `.faq-item` (FaqItem, invented kind=list — как в сданном исполнении Figma);
    `.nav-header` (Nav/Header; мобильный вариант — компакт с бургером,
    media query = аналог варианта viewport).
  - **Секционные** (адаптив через media query = аналог вариантов
    viewport=desktop|mobile): `.section-hero` (home-hero), `.section-manifesto`
    (home-about), `.section-directions` (home-classes), `.section-teachers`
    (invented, сетка home-classes), `.section-schedule` (timetable-schedule),
    `.section-pricing` (store-pricing + сетка home-classes), `.section-faq`
    (invented, faq-list-centered), `.section-cta` (home-events; тёмная —
    `data-theme="dark"`), `.section-footer` (home-footer; тёмная —
    `data-theme="dark"`).
  - **Типографика:** классы `.text-display/-h1/-h2/-h5/-body-lg/-body/-caption`
    из шагов tokens.json + `.text-body-bold` (вес-вариант ступени body,
    Manrope 500 — решение исходного прогона). Ступени «Small 14» референса в
    tokens.json нет — подписи карточек снэпятся к body (муть: показать на
    гейте 3). Неканонические h4/caption-sm лендингу home не нужны — не заводятся.
  - **Тёмные секции:** `[data-theme="dark"]` переопределяет семантические
    роли (fallback-html.md, зеркало режимов dark коллекции color исходного
    прогона).
- **Источник / evidence:** examples/yoga-school-demo/project/worklog.md
  («[Фаза 4] План библиотеки»); reference-inventory.md maps-to; content-doc.md.
- **Применённые rule ID:** `instances-only`, `no-detached-values`,
  `composition-cascade`, `tokens-before-pixels`
- **Отвергнутые альтернативы:** Button size=sm и компоненты дообогащения
  (Tag, Card/Event и др.) — на лендинге home не используются, в план не входят
  (не собирать «на всякий случай», figma-library-rules.md шаг 2).
- **Проверки / tier:** план сверен с составом секций content-doc (10 секций,
  все классы покрыты).
- **Риски:** шрифты Google Fonts грузятся с CDN — офлайн-просмотр покажет
  фолбэки; для deliverable допустимо, зафиксировать в отчёте.

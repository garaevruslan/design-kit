# Пример: yoga-school-demo

Полный прогон комплекта design-kit от референса до принятых Figma-макетов.
Учебный пример: смотри артефакты в `project/` в том порядке, в котором их
производит пайплайн.

- **Референс:** https://hollow-template.webflow.io/ (живой сайт, css-path)
- **Продукт:** лендинг вымышленной школы йоги «Опора» (1 страница, desktop 1440 + mobile 390)
- **Результат:** Figma-файл с variables, библиотекой из 19 компонентов и
  страницами `home/desktop-1440`, `home/mobile-390`; все 4 гейта пройдены

## Порядок чтения артефактов

1. `project/inputs.md` — вход: референс, бриф, масштаб (фаза 0)
2. `project/reference-study.md` — что и как извлечено из живого сайта (фаза 1)
3. `project/reference-inventory.md` — инвентарь паттернов референса (фаза 1)
4. `project/tokens.json` + `project/design-system.md` — система как данные (фаза 2, гейт 1)
5. `project/content-doc.md` — структура и тексты лендинга (фаза 3, гейт 2)
6. `project/verification-report.md` — три слоя приёмки (фаза 6, гейт 4)
7. `project/worklog.md` — **главный документ примера**: полный decision trail,
   гейты с формулировками утверждений, правки по фидбеку оператора и находки,
   которые стали правилами комплекта

## Чего здесь нет

- `project/reference-shots/` — 22 эталонных скриншота референса (~47МБ) не
  включены в репозиторий. В своём прогоне они создаются автоматически в фазе 1.
- Figma-файл — живёт в Figma, не в git. Артефакты содержат его структуру.

## Чему учит этот пример

Прогон нашёл и превратил в правила комплекта 5 реальных проблем: обязательный
specimen для гейта 1, проверку глифов шрифтов под язык контента, белую заливку
фреймов Figma по умолчанию, схлопывание FILL в hug-контейнерах, плотный
интерлиньяж дисплейных антикв в валидаторе. Ищи по worklog.md записи
«НАХОДКА ДЛЯ КОМПЛЕКТА» — это живой пример фазы 7.
